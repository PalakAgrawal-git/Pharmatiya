The one rule that governs the date

Both gates require Pharmatiya sign-off before we proceed. If sign-off is delayed, the timeline shifts by the same number of days — it does not compress. The same applies to Week-1 inputs: they are the only items with zero float, and a week’s delay on dataset clearance is a week’s delay on launch.

04

Build order, Weeks 4–5

Foundations first, then the components that carry credibility, then the pages that depend on them. Contact is built last because it is the only stateful page and needs the hosting decision.

Project foundationNext.js with static export, TypeScript strict, Tailwind configured against the approved tokens. Base layout, fonts self-hosted and subset.
Layout componentsHeader, Navigation, MobileNavigation with focus trap, Footer. Skip link and landmarks. Keyboard-tested before anything else is built on top.
UI primitivesButton, Input, SectionHeader, DataLabel. All states defined once: default, hover, focus, disabled, error.
Evidence componentsForestPlot, KaplanMeierGraphic, DatasetMap, TherapeuticMatrix, CaseStudy. Hand-authored inline SVG, each with a text alternative describing the finding.
HomeAssembles Hero, Proof, Services, NextGenTeaser, CTA. Built first because it exercises the most components and surfaces system gaps early.
Services and EvidenceThe two content-heaviest pages, sharing the service spine and the evidence components. Deep-link anchors verified against the homepage.
NextGen AI and AboutWorkflow diagram with the review bar; timeline and team grid. Both degrade gracefully if photography or product detail has not arrived.
ContactContactRouting with conditional fields, validation, live-region errors and a real success state. Last, because it depends on the hosting and form-handler decision.
Responsive and accessibility passEvery page at six widths. Axe and manual screen-reader testing. Contrast verified against the final palette, not the draft one.
Decision needed by Week 4

A statically exported site cannot process form submissions on its own. The contact form needs an endpoint — a form service, a serverless function, or the host’s built-in handler. This follows from input 10 and we will recommend an option in Week 1, but it must be settled before the Contact page is built.
